# Архитектура решения

## Компоненты

Kotlin / Jetpack Compose → ViewModel → ProcessingService → AudioDecoder / SpeechEngine → локальные файлы RecordingStore.

Интерфейс показывает реальные этапы обработки. Декодирование и вычисления вынесены с главного потока. Foreground service и ограниченный wake lock поддерживают обработку при свёрнутом приложении. JNI-объекты, аудиоресурсы и временные файлы освобождаются после работы.

## Обработка аудио и модели

1. Android MediaExtractor/MediaCodec декодирует файл. PCM приводится к mono float32, 16 кГц; размер и длительность ограничены до выделения чрезмерной памяти.
2. sherpa-onnx 1.13.8: pyannote segmentation 3.0 выделяет активность говорящих, WeSpeaker ResNet34 VoxCeleb извлекает признаки голосов, глобальная complete-link кластеризация формирует группы.
3. ERes2Net VoxCeleb уточняет группы по чистым участкам с сохранением опор. Если пригодных длинных опор меньше двух, бесполезное извлечение пропускается.
4. Дополнительный консервативный проход использует уже полученные нативные признаки. Он объединяет только подтверждённые фрагменты с достаточным сходством и отрывом; одновременная речь препятствует слиянию. Центрирование и экспериментальные варианты кластеризации выключены.
5. GigaAM v3 CTC int8 распознаёт русскую речь и пунктуацию по интервалам. Контекст учитывает границы соседних реплик; текст при перекрытии не дублируется как доказательство второго голоса.
6. GTCRN используется при явно выбранном повторном распознавании с подавлением шума, а не безусловно для всей записи.

Модели и токены входят в APK. ONNX Runtime работает через JNI. Собственное расширение сохраняет исходный API и передаёт Kotlin признаки и интервалы, уже вычисленные нативным проходом. Исходник, описание формата, проверка целостности и сборочные скрипты находятся в `src/mobile/native` и `scripts`.

## Производительность

Образцы для уточнения ограничены общим бюджетом; чистые участки дополняют надёжные опоры. WAV-буфер использует известный размер, где это возможно. Не загружается модель уточнения, если её алгоритм не может изменить результат. ARM64 использует до четырёх потоков; x86_64 сохраняет два. Замеры на конкретном телефоне приведены в результатах тестов.

## Хранение и интеграции

Записи и метаданные находятся в приватном хранилище приложения, JSON записывается атомарно. Импорт и экспорт используют системный выбор файлов без доступа ко всему накопителю. Сетевого API, облачного распознавания и регистрации нет. Экспорт и отправка запускаются пользователем.

## Зависимости

JDK 17, SDK 36, Gradle 9.3.1, AGP 9.1.0, Kotlin/Compose, sherpa-onnx 1.13.8, ONNX Runtime. Точные версии — в Gradle; лицензии и хеши моделей — в MODEL_LICENSES.md и assets/models/manifest.json.
